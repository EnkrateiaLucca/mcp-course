Lesson 2: The MCP server in production

Goal: you can take research_server.py (module 04) and server.py (module 05) and list the six changes that make the server safe to run on the internet, with the code for each.

TL;DR

The problem: Your tools server works on a tunnel, but it trusts every caller, saves files on a disk that disappears, and will fetch any web address it is given.

The shape of the solution:

  • Lock the door properly: list the web addresses the server answers to, instead of switching the check off.
  • Know who is calling: start with one shared password, then move to real logins (OAuth). The tools read the user's name from the login, never from what the AI typed.
  • Keep data off the server's own disk: save briefs in a database or file store, one folder per user.
  • Don't fetch everything: refuse private and internal addresses, so a bad web page can't trick the server into reading your cloud's secrets.

Think of it like: A shop that answers only its own street address, checks ID at the door, keeps records in a central filing cabinet, and won't deliver to a back office.

Change 1: Keep the HTTP app stateless

Module 05 has this right. One function builds the ASGI app, and both uvicorn and the platform import it.

app = mcp.streamable_http_app(
    stateless_http=True,    # no per-client session: any replica answers any request
    json_response=True,     # one JSON body per request; no SSE (serverless-friendly)
    transport_security=SECURITY,   # change 2
)

Use json_response=False only when a tool must stream progress notifications. The 2026-07-28 spec scopes that stream to the one request, so it still needs no sticky routing. If a reverse proxy sits in front, the spec recommends the X-Accel-Buffering: no response header so the proxy does not buffer the stream.

Change 2: Pin Host and Origin instead of turning the check off

Module 05 sets enable_dns_rebinding_protection=False to stop the 421 Misdirected Request behind the tunnel and Vercel. The fix works, but it removes a check the spec makes mandatory: "Servers MUST validate the Origin header on all incoming connections." Keep the protection on and list your real hostnames:

from mcp.server.transport_security import TransportSecuritySettings

PUBLIC_HOST = os.environ.get("PUBLIC_HOST", "")   # e.g. research-mcp.example.com

SECURITY = TransportSecuritySettings(
    enable_dns_rebinding_protection=True,
    allowed_hosts=["127.0.0.1:*", "localhost:*", *filter(None, [PUBLIC_HOST])],
    allowed_origins=[],   # requests WITHOUT an Origin header pass (server-to-server);
                          # add browser origins here only if a trusted web app calls you
)
  • The SDK matches hosts exactly. name:* allows any port. A Vercel preview deployment has a different hostname, so it needs its own entry.
  • An agent or a connector backend calls you server-to-server and sends no Origin. The SDK lets those requests through. A malicious web page in a user's browser sends its own Origin and gets rejected.

Change 3: Move tool state off local disk, and key it by tenant

research_topic writes to workspace/briefs/ next to the server. On Vercel the function filesystem is read-only except /tmp, and /tmp disappears between invocations. On Cloud Run or Kubernetes each replica has its own disk. Either way, list_briefs on replica B cannot see a brief that replica A wrote.

def _brief_key(tenant: str, topic: str) -> str:
    return f"{tenant}/briefs/{_slugify(topic)}.md"

# dev:  (BRIEFS_ROOT / _brief_key(...)).write_text(brief)
# prod: object_store.put(_brief_key(...), brief)    # S3, R2, GCS, Vercel Blob, or a Postgres table

Two rules come with this change:

  1. The tenant comes from the verified token, never from a tool argument. If tenant were a parameter, a prompt-injected agent could read another user's briefs.
  2. Keys replace paths. The path-traversal check in read_brief becomes "does this key start with {tenant}/briefs/".

Change 4: Climb the auth ladder

Rung 1: static bearer token (modules 04 and 05 today)

The middleware seam is right. Fix one line: compare secrets in constant time, the way the cookbook server does. A plain != leaks timing information.

import secrets

class BearerAuth(BaseHTTPMiddleware):
    async def dispatch(self, request, call_next):
        got = request.headers.get("authorization", "")
        if not secrets.compare_digest(got, f"Bearer {AUTH_TOKEN}"):
            return JSONResponse({"error": "unauthorized"}, status_code=401)
        return await call_next(request)

A single shared token says "this caller is the agent service". It does not say which user. That is acceptable for row 1 of the table above.

Rung 2: per-user tokens with OAuth 2.1 (the spec's answer)

Your MCP server becomes an OAuth resource server. An authorization server (Auth0, Okta, Keycloak, your IdP) issues the tokens. The v2 Python SDK does the protocol parts for you:

  • It publishes the Protected Resource Metadata document at /.well-known/oauth-protected-resource (RFC 9728).
  • It answers an unauthenticated request with 401 and a WWW-Authenticate header that points at that document. Clients such as Claude Code then discover the auth server and run the login flow.
  • It passes every bearer token to a verifier you write.
from pydantic import AnyHttpUrl
from mcp.server.mcpserver import MCPServer
from mcp.server.auth.settings import AuthSettings
from mcp.server.auth.provider import AccessToken, TokenVerifier
from mcp.server.auth.middleware.auth_context import get_access_token

SERVER_URL = os.environ["PUBLIC_URL"]        # https://research-mcp.example.com/mcp

class JWTVerifier(TokenVerifier):
    async def verify_token(self, token: str) -> AccessToken | None:
        claims = verify_jwt(token, issuer=ISSUER, audience=SERVER_URL)  # your IdP's JWT library
        if claims is None:
            return None                       # SDK answers 401 with WWW-Authenticate
        return AccessToken(
            token=token, client_id=claims["azp"], subject=claims["sub"],
            scopes=claims["scope"].split(), expires_at=claims["exp"], resource=SERVER_URL,
        )

mcp = MCPServer(
    "research-assistant",
    token_verifier=JWTVerifier(),
    auth=AuthSettings(
        issuer_url=AnyHttpUrl(ISSUER),
        resource_server_url=AnyHttpUrl(SERVER_URL),
        required_scopes=["research"],
        validate_token_resource=True,         # reject tokens minted for another API
    ),
)

@mcp.tool()
def list_briefs() -> dict:
    """List the caller's saved briefs."""
    tenant = get_access_token().subject       # identity from the token, not from the model
    ...
Audience is the check people skip. A token minted for some other API must fail here. Without the audience check, any valid token from your IdP opens your tools. The MCP docs call this the token passthrough problem. validate_token_resource=True plus resource= in AccessToken enforces it.

No tool body changes between rung 1 and rung 2, apart from reading the tenant. That is the seam module 04 teaches.

Change 5: The server holds the tool credentials, and it fetches safely

Credentials. If research_topic moves from DDGS scraping to a paid search API, the API key goes in the MCP server's environment or secret manager. The agent never sees it. The secure-deployment guide recommends this pattern: the agent calls a tool, and the authenticated request happens outside the agent's boundary.

SSRF. _fetch_page fetches any http(s) URL that a search result contains, and it follows redirects. In a cloud deployment, a poisoned search result can point at http://169.254.169.254/ (the cloud metadata service) or at an internal admin page. Allow only public addresses, and check every redirect hop:

import ipaddress, socket
from urllib.parse import urlparse

def _is_public(url: str) -> bool:
    p = urlparse(url)
    if p.scheme not in {"http", "https"} or not p.hostname:
        return False
    try:
        infos = socket.getaddrinfo(p.hostname, p.port or 443)
    except socket.gaierror:
        return False
    return all(ipaddress.ip_address(info[4][0]).is_global for info in infos)

# in _fetch_page: follow_redirects=False, then loop up to 3 hops,
# calling _is_public() on each Location before you request it.

This check has a known ceiling: DNS can change between the check and the request. For a hard guarantee, send all fetches through an egress proxy that enforces the same rule (lesson 4).

Change 6: Health, limits and a pre-flight against the public URL

  • Request size. streamable_http_app() takes max_request_body_size (default 4 MiB). Lower it if your tools take short arguments.
  • Time limits. research_topic runs one search and up to five page fetches with a 10-second timeout each. Check your platform's function duration limit. On Vercel, set it in vercel.json. Or fetch the pages concurrently.
  • Pre-flight. Run uv run test_client.py https://<public-host>/mcp after every deploy. Only a run against the public hostname catches Host-header and auth problems.
  • Logs. Log Mcp-Method, Mcp-Name, the token subject and the latency for each request. Never log the token.

Check yourself

Why must the tenant come from the token and not from a tool argument?The model fills tool arguments, and injected content can steer the model. Only the verified token is outside the model's control.
What does the audience (resource) check stop?A token that your IdP issued for a different API being accepted by your MCP server (token passthrough).
Module 05 works over the tunnel with protection disabled. What did it give up?Host and Origin validation, which stops a malicious web page in a browser from reaching the server through DNS rebinding. The spec requires Origin validation.
Two replicas run the module 04 server unchanged. A user creates a brief, then lists briefs, and sees nothing. Why?The brief was written to replica A's local disk, and the list request landed on replica B.
